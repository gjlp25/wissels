# Matchday improvements — acceptance and compatibility

Approved scope: statuses, manual matchday mode, reversible/protected schedule edits, factual fairness explanation, and safer backups. Static/local-only; no PWA, backend, account, cloud, deployment or platform gate changes.

## Acceptance

- New matches start as Concept. Concept/Klaar do not count toward totals or generator history. Gespeeld uses the saved, editable schedule as the actual record; no separate fictional actual-minute estimate. Direct Keeper per periode edits update only the selected period, without regenerating any other slots or changing proposal keeper blocks. A newly selected bench player is added to the field and the count warning asks the user to complete the paired swap.
- Legacy status-less matches dated strictly before the local calendar day count as inferred Gespeeld; today/future/undated matches are inferred Klaar. Display the inference and require explicit choice for certainty. Never rewrite their status or schedule merely on load/import. Date fallback is intentionally conservative, not proof that a match happened.
- Match mode shows the selected period, current field/bench/keeper and next in/out/keeper; bounded previous/next controls, no automatic timer or writes on period selection.
- Compute automatic collision-free display positions on a copy so loading, period switching and undo do not rewrite saved positions. Persist one schedule-only undo snapshot per match before table/drag edits, regeneration and setting changes. Undo restores attendance, category, interval, keepers, slots, keeperBySlot, positions and manual flag, not later opponent/date/status edits. Legacy schedules are protected as potentially manual. Manual and played schedules require explicit confirmation before generation or schedule-setting changes. Cancellation changes nothing.
- Explain the real priority order: minimize consecutive bench occurrences across the full schedule under keeper/field constraints, then current minutes, first-bench history at the start, historical attendance-relative minute deficit, switches; random ties. Keeper time is included in total playing time, not separately optimized. Show factual total/keeper/outfield, present-match count and deficit relative to each attended match's average. No invented per-player causal reasons.
- Validate the entire backup before any replacement or backup offer. Then offer downloading current data, then require replacement confirmation. Invalid/cancelled imports leave complete storage unchanged. Show last download-request time (not proof of a saved file); gently remind after three additional played matches since that request. If metadata storage fails, the download still proceeds and an explicit message says its time was not recorded; retain previous metadata in memory/storage. If replacement storage fails, report the failure and retain all current records and selection. Both normal export and the pre-restore safety download refuse stale-tab snapshots rather than exporting either stale or another tab's live records.

## Persistence and backwards compatibility

Keep `wissels-jo9`, existing IDs, unknown additive fields, schedules and manual positions. Add optional `status`, `manual`, `undo` and top-level `backup` metadata, without a mandatory format version. Existing team backups and pre-team `players` backups remain importable; pre-team conversion preserves player/match IDs. Deleted historical players may remain as referenced IDs in attendance/schedules (the existing app permits player deletion); validation must not destroy these records. Invalid shape, duplicate team/match IDs or player IDs within a team, invalid dates/categories/intervals/statuses, bad positions, inconsistent slot/keeper references or undo snapshots are rejected before replacement. Incorrect field counts from manual edits are allowed, still visibly warned, because those are recoverable user work. Short/empty legacy keeper block arrays are allowed. Unsupported future format versions fail closed.

Per-team player IDs from older versions may coincide across teams and are retained. Import identifiers must match the app-generated alphanumeric/hyphen/underscore contract, excluding `constructor`, `prototype` and `__proto__`; inherited method names such as `toString` and `valueOf` remain compatible and render/count normally. Invalid identifiers are rejected rather than repaired. The optional safety download during restore does not update metadata in the current browser, preserving complete state on cancellation. One undo level is included in JSON backups; undo is not a deletion recovery system. Total played match count is a reminder heuristic, not an audit trail: deleting/reclassifying matches can reduce it. Last download-request metadata is portable with backups; the app cannot know whether the browser/user saved the download. localStorage remains unencrypted, origin/browser/device-local and finite; existing stale-snapshot guard is not an atomic multi-tab lock.

## Verification

Full `node --test`, pure status/statistics/import tests and real handler tests. Approved behavior supersedes visual-only script hashes: retain layout/asset checks and replace obsolete frozen-script assertions with asset/loading and behavior coverage, not new hashes. Existing generation-history fixtures explicitly mark historical matches played. Real isolated-browser fixtures compare complete localStorage across reload, undo and import, exercise cancellation/invalid imports, phone controls and inspect refreshed manual screenshots. No live user storage is accessed.
